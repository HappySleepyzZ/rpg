# 结局判定系统

## 1. 系统定位

结局判定系统用于将玩家在主线、关系线、角色决断和世界路线中的长期选择，汇总为最终结局与后日谈。

它不应只在最终战后读取一个选项，而应根据全程行为生成：

- 世界结局。
- 主角归属。
- 同伴个人结局。
- 核心 NPC 结局。
- 组合后日谈。
- 未完成关系的残留后果。

设计目标：

> 让结局像是玩家一路处理关系和价值选择的自然结果，而不是结尾菜单的选项奖励。

## 2. 结局层级

建议分为四层：

```text
Layer 1: 世界结局
Layer 2: 主角结局
Layer 3: 角色个人结局
Layer 4: 组合后日谈
```

### Layer 1 世界结局

回答：

```text
这个世界最终走向哪里？
```

### Layer 2 主角结局

回答：

```text
玩家扮演的角色最终如何定义自己？
```

### Layer 3 角色个人结局

回答：

```text
每个重要角色是否获得了自己的归属？
```

### Layer 4 组合后日谈

回答：

```text
高权重关系在战后如何继续、断开或留下遗憾？
```

## 3. 判定顺序

推荐判定顺序：

```text
1. 读取不可逆锁定状态
2. 判定世界路线
3. 判定主角路线
4. 判定角色生死和可用性
5. 判定角色个人结局
6. 判定核心 NPC 状态
7. 判定强承诺兑现情况
8. 判定组合后日谈
9. 输出最终文本与演出
```

不可逆锁定状态包括：

- 角色死亡。
- 关系永久决裂。
- 关键真相未揭露。
- 某组织被毁灭。
- 某承诺被主动背弃。
- 某个世界路线已被锁死。

## 4. 世界路线变量

建议使用 2 到 4 条抽象价值轴，而非善恶值。

示例三轴：

```text
Order    秩序
Origin   源流
Will     自主
```

含义：

- `Order`：维护现有秩序、制度、传统、稳定。
- `Origin`：理解旧世界、被排斥者、原初力量或被压制的真相。
- `Will`：拒绝替别人决定命运，支持个体自主选择。

这三轴可以替换为具体项目所需的价值轴。

设计原则：

- 不要做简单善恶。
- 每条路线都应有正当性和代价。
- 真结局不应只是数值全高，而应符合主题条件。

## 5. 世界结局类型

通用结构可设计为：

### 秩序结局

条件倾向：

```text
Order 高
Will 不足
```

结果：

世界稳定下来，但旧制度的问题没有完全解决。

### 回归结局

条件倾向：

```text
Origin 高
Will 不足
```

结果：

被压制的旧力量或旧真相回归，世界被重组，但代价巨大。

### 自主结局

条件倾向：

```text
Will 高
多个关键角色完成自我判定
Order 与 Origin 未形成单边吞没
```

结果：

世界不完全回到旧秩序，也不完全被原初力量吞没，而是开辟新规则。

### 崩坏结局

条件倾向：

```text
关键战败
Will 低
核心角色多线崩坏
```

结果：

世界结构失控，角色进入生存或毁灭后日谈。

## 6. 个人结局矩阵

每个核心角色使用两个基础轴：

```text
Attachment 牵绊
Autonomy   自我
```

矩阵：

```text
牵绊高 + 自我高 = 成熟归属
牵绊高 + 自我低 = 被关系吞没
牵绊低 + 自我高 = 切断旧因果，独自前行
牵绊低 + 自我低 = 空壳、逃避或坏结局
```

解释：

- 成熟归属不等于大团圆。
- 独自前行不等于坏结局。
- 牵绊高但自我低往往是危险结局。
- 自我低是多数悲剧结局的关键风险。

## 7. NPC 结局

重要 NPC 不应只作为主角关系的附属奖励。

NPC 结局建议读取：

```text
relationship_tags
promise_flags
truth_revealed
accountability
survival_state
world_route
```

通用 NPC 结局类型：

- 死亡赎罪。
- 生还但接受清算。
- 生还并共同重建。
- 隐名离去。
- 被公开审判。
- 被放逐。
- 自愿守望。
- 沉睡或封印。
- 彻底决裂。

关键原则：

> 死亡不能成为唯一赎罪方式。

如果玩家长期投入理解、追责和召回，系统应允许“活下来承担后果”的结局成立。

## 8. 强承诺兑现

强承诺应在结局中优先读取。

承诺类型：

- 活着回来。
- 一起离开。
- 回到某地。
- 公开真相。
- 不再干涉。
- 接受审判。
- 等待重逢。
- 认真告别。

兑现方式不必总是成功。

示例：

```text
承诺：活着回来
结果 A：角色生还，承诺兑现。
结果 B：角色死亡，但留下明确回应，承诺悲剧性破裂。
结果 C：角色生还却没有回来，承诺转化为未完成后日谈。
```

重点是承诺必须被文本正面处理，不能被系统忽略。

## 9. 组合后日谈

组合后日谈用于处理高权重关系的战后状态。

判定条件：

```text
双方存活
关系阶段达到阈值
特定标签成立
没有互斥锁
世界路线允许
```

组合后日谈类型：

- 共同治理。
- 同行远游。
- 暂时分别。
- 一方守望另一方。
- 公开关系或公开真相。
- 互相清算后重新开始。
- 无法和解但彼此承认。
- 一方继承另一方遗志。

注意：

组合后日谈不是恋爱专属。它可以是师徒、亲缘、宿敌、共犯、同伴、组织关系。

## 10. 结局文本生成规则

结局文本应按以下顺序组织：

```text
1. 世界状态
2. 主角去向
3. 核心角色个人归属
4. 重要 NPC 后果
5. 高权重关系后日谈
6. 未解决问题或未来伏笔
```

文本原则：

- 不给所有结局贴简单好坏标签。
- 明确呈现代价。
- 尊重玩家强承诺。
- 让角色选择与其前文状态一致。
- 对未完成关系保留遗憾，而不是强行圆满。

## 11. 判定伪代码

```text
resolveEnding(gameState):
  locks = collectIrreversibleLocks(gameState)
  worldEnding = resolveWorldRoute(gameState.worldAxes, locks)
  protagonistEnding = resolveProtagonist(gameState, worldEnding)

  personalEndings = []
  for character in coreCharacters:
    if character.isAvailable(locks):
      personalEndings.add(resolvePersonalEnding(character, gameState, worldEnding))
    else:
      personalEndings.add(resolveLockedEnding(character, locks))

  npcEndings = []
  for npc in importantNPCs:
    npcEndings.add(resolveNPCEnding(npc, gameState, worldEnding))

  pairEndings = resolvePairEndings(gameState, personalEndings, npcEndings, worldEnding)

  return composeEndingText(worldEnding, protagonistEnding, personalEndings, npcEndings, pairEndings)
```

## 12. 最小可行版本

MVP 建议：

```text
世界路线：3 到 4 种
核心角色：3 到 4 名
每名角色个人结局：4 种
重要 NPC：3 到 5 名
强承诺槽：1 到 2 个
组合后日谈：8 到 12 条
```

先确保结局差异来自系统判定，而不是单纯增加文本数量。
