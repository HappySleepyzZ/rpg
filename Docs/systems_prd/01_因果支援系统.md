# 因果支援系统

## 1. 系统定位

因果支援系统是一套用于承载复杂人物关系的叙事 RPG 底层系统。

它的目标不是表达“角色是否喜欢玩家”，而是表达一段关系如何被理解、修复、拒绝、继承或切断。

适用场景：

- 剧情核心由角色关系推动。
- 角色之间存在旧债、隐瞒、保护、背叛、亏欠、依赖或身份错位。
- 结局需要根据玩家如何处理关系来变化。
- 不希望使用传统好感度将复杂情感简化为数值高低。

核心体验：

> 玩家不是刷好感，而是在一次次剧情选择中为关系定性。

## 2. 设计目标

本系统需要达成以下目标：

1. 允许一段关系同时存在正负情绪。
2. 支持“理解但不原谅”“追责但仍在乎”“切断但不仇恨”等中间态。
3. 让关系状态影响剧情分支、角色行为、战斗协作、结局文本。
4. 避免玩家通过礼物、重复对话等低成本行为绕过关键剧情判断。
5. 让玩家能理解关系为何走向某个结局。

## 3. 底层数据结构

每一段重要关系都抽象为一条 `Bond`。

```text
Bond {
  id
  actor_a
  actor_b
  stage
  trust
  wound
  attachment
  autonomy
  tags[]
  promises[]
  revelations[]
  locks[]
}
```

字段说明：

- `id`：关系唯一标识。
- `actor_a / actor_b`：关系两端角色，可以是玩家角色、同伴、NPC、组织或抽象对象。
- `stage`：关系阶段，用于 UI 展示和剧情门槛。
- `trust`：信任度，决定对话深度、介入资格、协作可能性。
- `wound`：伤害值，代表裂痕、旧债、未清算的问题。
- `attachment`：牵绊值，代表这段关系是否仍被双方视为重要。
- `autonomy`：自我值，代表角色是否能不被这段关系吞没。
- `tags`：关系定性标签。
- `promises`：强承诺，通常在章节终点或终局前写入。
- `revelations`：已揭露真相，决定角色是否具备做出成熟判断的信息。
- `locks`：不可逆状态，如死亡、决裂、誓言、公开审判等。

## 4. 四个核心数值

### Trust 信任

信任不等于喜欢。

它代表角色是否愿意：

- 说出真相。
- 接受玩家介入。
- 在战斗或危机中配合。
- 相信玩家的判断。

### Wound 伤害

伤害不等于厌恶。

它代表关系中尚未处理的裂痕：

- 被欺骗。
- 被控制。
- 被利用。
- 被遗弃。
- 被替代。
- 被迫承担责任。

高伤害关系也可以有高牵绊。

### Attachment 牵绊

牵绊代表这段关系是否仍然重要。

牵绊高可能导向：

- 和解。
- 纠缠。
- 互相拯救。
- 互相毁灭。

它必须与自我值共同判定，不能单独作为好结局指标。

### Autonomy 自我

自我代表角色是否还能作为独立个体存在。

自我低的角色容易：

- 成为他人的工具。
- 被旧关系定义。
- 以牺牲自己完成关系闭环。
- 进入依附、替代、容器、赎罪等结局。

自我高的角色更可能做出成熟选择，但不代表一定与玩家站在同一边。

## 5. 关系标签

关键选择不应只做数值增减，而应写入关系标签。

基础标签建议：

```text
理解
追责
宽恕
审判
继承
切断
召回
自主
隐瞒
公开
利用
保护
拒绝
承认
告别
```

标签设计原则：

- 标签可以并存。
- 标签不必天然分正负。
- 标签应代表玩家对关系的判断，而不是角色对玩家的好恶。
- 标签应在结局判定和关键剧情中被读取。

示例：

```text
理解 + 追责
```

表示玩家承认对方动机，但不抹除其造成的伤害。

```text
宽恕 + 切断
```

表示玩家不再仇恨对方，但也不愿继续这段关系。

```text
召回 + 审判
```

表示玩家不允许对方以死亡逃避责任，而要求其活下来接受后果。

## 6. 关系阶段

关系阶段用于 UI 和剧情门槛。

通用阶段可设为：

```text
未知 -> 接触 -> 裂痕 -> 接近 -> 坦白 -> 定性 -> 归属
```

阶段不等同于好感等级。

例如：

- `坦白` 可能导致和解，也可能导致决裂。
- `归属` 可能是共同生活，也可能是认真告别。
- `裂痕` 不一定是坏状态，它可能是关系真正开始被看见。

## 7. 强承诺机制

强承诺是高权重关系选择。

它通常发生在：

- 章节终点。
- 角色个人线高潮。
- 最终战前。
- 重大离别前。

强承诺不是恋爱誓约，而是玩家对某段关系作出的明确归属判断。

类型示例：

- 要求对方活下来。
- 要求对方承担责任。
- 承诺战后同行。
- 承诺公开真相。
- 承诺替对方守住某物。
- 承诺不再干涉对方选择。
- 明确告别。

设计规则：

1. 强承诺数量应有限，制造取舍。
2. 强承诺必须改变后续判定权重。
3. 强承诺不保证幸福结局，只保证该承诺会被剧情认真处理。
4. 强承诺不能绕过前置真相和关系积累。

## 8. UI 表现

不建议显示：

```text
好感度 87/100
```

建议显示：

```text
关系阶段：坦白
关系状态：理解 / 追责 / 未完成的约定
已知真相：3/5
未处理裂痕：公开身份、旧日背叛
```

更适合的界面形式：

- 关系图。
- 因果图。
- 记忆碎片页。
- 角色档案中的关系状态词。
- 章节回顾中的关键承诺。

玩家应该感到自己在整理一张关系网，而不是管理一组数值。

## 9. 内容制作规范

每个关键关系节点至少提供三类表达：

```text
理解型：我看见你的动机。
追责型：我指出你的伤害。
自主型：我要求自己或对方重新选择。
```

避免只有：

```text
原谅 / 不原谅
相信 / 不相信
喜欢 / 讨厌
```

因为复杂关系的价值往往存在于中间态。

## 10. 最小可行版本

MVP 建议：

```text
核心关系：4 到 6 条
核心数值：trust / wound / attachment / autonomy
基础标签：理解、追责、宽恕、审判、继承、切断、召回、自主
强承诺槽：1 到 2 个
关系阶段：5 到 7 阶
```

先确保系统能稳定生成差异明显的个人结局，再扩展更多支线关系。
