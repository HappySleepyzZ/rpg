## 设计方向

- 目标是单机 RPG 原型。
- 视角方向：第三人称自由镜头，不做横版。
- 第一阶段重点是探索和剧情，战斗后续迭代。
- 世界观可以后续包装，但最小原型阶段要去包装化，不要把“修仙、灵力、法术”等词写进核心系统。
- 美术可以先白盒，后续再决定渲染、美术风格和具体资产。
- 原型 001 目标大致是：第三人称探索、基础交互、后续加入队友、敌人、任务闭环。
- 战斗方向讨论过即时动作、回合制、半即时。结论是程序架构要保持可替换，不要早期把某一种战斗表现硬写死。
- 参数应尽量抽出来，不要写死在代码里。可调表现参数优先暴露到 UE 编辑器或蓝图，便于用户自己调试。

## 架构原则

- UE 底层是 C++，可以像 Python 一样声明类，但需要头文件、源文件、反射宏和编译。
- 稳定规则和底层系统适合放 C++。
- 表现参数、动画、美术资源和关卡配置适合放 Blueprint / DataAsset / 编辑器资产。
- 角色、战斗、任务、交互等系统应该各自有类或组件，避免所有逻辑堆在一个蓝图里。
- 目前不急着做复杂架构，但要从一开始保持可维护。

## 闪避当前状态

- LeftShift 现在不是持续加速 sprint，而是一段一次性 dash / dodge。
- 当前暴露到 `BP_PlayerCharacter` 的闪避参数：
  - `DashStrength`
  - `DashDuration`
  - `DashCooldown`
  - `bDashUseInputDirection`
  - `DashAnimation`
  - `DashAnimationBlendIn`
  - `DashAnimationBlendOut`
  - `DashAnimationPlayRate`
- 当前实现使用 `LaunchCharacter` 产生短时间高速位移。
- 闪避动画使用 `UAnimMontage::CreateSlotAnimationAsDynamicMontage` 从 `DashAnimation` 动态创建 montage 播放。
- 用户问过 montage 是什么。需要解释为 UE 动画系统里的“可插入播放片段”，中文常叫“动画蒙太奇”，不是电影剪辑概念本身。
- 当前默认 `DashAnimation` 曾指向：
  - `/Game/Characters/Mannequins/Anims/Unarmed/Jump/MM_Dash`
- 用户认为这个动作不像闪避，需要替换。
- 新增脚本：
  - `Scripts/set_dash_animation_from_imported_assets.py`
- 该脚本用途：
  - 扫描 `/Game` 下 `Dodge / Evade / Roll / Dash / Slide / Step` 相关动画。
  - 排除 `Attack / Slash / Hit / Impact / Death / Jump / Fall / Land` 等明显不合适的动画。
  - 自动把最合适候选设置到 `BP_PlayerCharacter.DashAnimation`。
- 脚本已通过只读 AST 语法检查。
- 普通 `py_compile` 被 Windows 权限挡住，因为它尝试写 `Scripts\__pycache__`。
